# 문서 문체·구조 규칙

프레임워크의 어느 층을 쓰든 이 규칙을 적용한다. 이미 있는 문서를 정리할 때는
아래 절차를 그대로 따른다.

## 1. 문체

| 규칙 | 적용 |
|---|---|
| 검증 가능한 서술 | `~할 수 있어야 한다`, `~해야 한다`, `~하지 않는다`로 종결 |
| 주체 명시 | `사용자는 ~할 수 있어야 한다` / `시스템은 ~해야 한다` |
| 하지 않아도 되는 것 | 사용자가 판단·조작하지 않아도 되는 지점을 명시 |
| 감정 표현 제거 | 귀찮다, 어렵다, 번거롭다, 죽는다, 당했다, 무방비, 헛되이 |
| 구어 연결 제거 | 문두의 그래서·하지만, `~거든요`, `~해요`, `~에요` |
| 소제목 명사형 | "어디서 실행할 것인가" → "실행 위치" |
| 반복 제거 | 구체 항목은 나열하되 같은 말을 장마다 되풀이하지 않는다 |

**구성 순서: 사용자 행동 → 시스템 행동 → 기대 효과.**

### 층별 예외

| 층 | 문체 |
|---|---|
| 정의·계약 (1~8) | 위 규칙 전면 적용. 요구사항은 `~해야 한다`로 끝낸다 |
| 결정 (9) | 서술체 허용. 왜 그렇게 판단했는지가 본문이라 단정문만으로는 안 된다 |
| 현행 (10~12) | 현재형 평서문. `~한다`. 요구사항체를 쓰지 않는다 |
| 기록 (13~15) | 과거형 사실 기록. `~했다`, `~였다`. 판단과 사실을 섞지 않는다 |
| 종결 (16~18) | 판정문. `달성`, `미달`, `해당 없음`을 명시한다 |

### 보정 예시

before

> 기록을 남기는 데는 두 가지 일이 섞여 있어요. 적는 일과 정리하는 일이요.
> 적는 건 쉬워요. 정리는 어려워요. 제목을 뭐라고 할지, 태그를 뭘 달지를 그 순간에
> 정해야 하거든요. 이게 귀찮아서 사람들은 정리를 포기하거나 아예 안 적어요.
> 그래서 순서를 바꿔요. 적을 때는 아무것도 정하지 않고, 정리는 나중에 도구가 해요.

after

> **기록과 정리를 분리한다.**
>
> - `FR-01` 사용자는 내용을 알게 된 즉시 별도의 분류나 정리 없이 기록할 수 있어야 한다.
> - `FR-02` 기록 시 제목, 분야, 태그, 기존 노트와의 연관 관계를 사용자가 직접
>   판단하지 않아도 되어야 한다.
> - `FR-03` 분류, 태그 지정, 기존 노트와의 연결은 이후 도구가 수행한다.
>
> 이를 통해 기록 과정의 부담을 줄이고 사용자가 기록 자체에 집중할 수 있도록 한다.

## 2. 제거 검토

**제거 후보**

- 첫 줄이 "N장과 같다"로 시작하는 절 — 참조 대상에 통합하고 절을 삭제한다
- 해소된 미결·초안 잔재 — 본문에 이미 반영됐다면 목록에서 뺀다
- 채택하지 않은 설계에만 존재하던 위험·제약 메모
- 요구사항도 제약도 아닌 기록 (명명 후보 검토, 잡담성 부록)
- 장 구성 안내 문단 — 목차를 넣으면 대체된다
- 같은 사실을 반복하는 도입 문단
- 다른 층에 이미 있는 내용의 사본 — 원본 층에 두고 참조로 바꾼다

**제거하면 안 되는 것**

- 다른 절이 `근거는 ADR-nnnn`으로 참조하는 항목. 빼면 "왜"에 답이 없어진다
- 결론이 "불가능"·"해당 없음"뿐이어도 스코프 방어선 역할을 하는 항목
- 탈락한 대안 안에 섞여 있는, 현행 설계가 의존하는 실측 근거
- 수치·명령어·출력 등 검증 기록
- 결정층(9)의 항목 전부. 결정 기록은 지우지 않고 `상태: 폐기`로 표시한다

**판단 기준: 지우기 전에 그 항목을 참조하는 곳이 있는지 먼저 grep한다.**

## 3. 구조

- **목차**: h2/h3 전체를 앵커 링크로. 헤더 메타 블록 바로 아래 배치
- **앵커 생성**: 소문자화 → `[^\w\s-]` 제거 → 공백을 하이픈.
  em dash·괄호·마침표가 든 제목은 직접 쓰지 말고 스크립트로 생성한다
- **교차참조**: 절을 옮기거나 지우면 항목 번호와 ID 참조를 전부 갱신한다
- **번호 정합**: 헤더의 "미결 N건"과 실제 표 행 수처럼 서로 맞아야 하는 값을 대조
- **층 경계 유지**: 편집 중에 다른 층의 내용이 흘러들어오면 원래 층으로 옮긴다

## 4. 절차

1. 파일 전체를 읽는다. 부분만 보고 고치지 않는다
2. 원본을 스크래치패드에 백업한다
3. 문체 → 제거 → 구조 순으로 진행한다
4. 스크립트로 편집할 때는 치환 전 `assert count == 1`로 대상 유일성을 확인한다
5. 검증 grep을 돌린다

```bash
grep -nE '거든요|해요|이에요|예요|^그래서 |^하지만 |귀찮|어렵|죽는다|무방비' FILE
grep -n '<지운 항목 번호>\|<지운 항목 제목>' FILE   # 끊긴 참조 확인
```

`project-doc-framework` 스킬을 불러 그 절차를 따른다. 대상 디렉터리는
`$1`이고, 비어 있으면 `docs`다.

## 순서
1. **먼저 저장소를 읽는다.** 파일 수, 언어, 커밋 이력, README 유무를 본다.
   사용자에게 규모를 묻기 전에 스스로 판단할 근거를 모은다.

2. **프로파일을 판정하고 근거를 한 줄로 말한다.** 예: "기능 하나짜리에 배포 대상이
   없어 M으로 본다." 판정이 애매하면 그때만 `AskUserQuestion`으로 M/L을 묻는다.
   M 아래는 없다. 아무리 작아도 M 에서 시작한다.

3. **이미 있는 문서를 확인한다.** 대상 디렉터리에 파일이 있으면 **덮어쓰지 않는다.**
   무엇이 있는지 보고하고, 승급(파일 추가)인지 신규 생성인지 판정한 뒤 진행한다.

4. **템플릿을 복사한다.** 스킬 디렉터리의 `templates/`에서 해당 프로파일 파일만
   가져온다. 프로파일에 없는 파일은 만들지 않는다.

   | 프로파일 | 만드는 것 |
   |---|---|
   | M | `charter.md`, `journal.md`, `design.md`, `decisions/` |
   | L | + `report.md` |

   M 에서 만드는 문서에서는 템플릿의 `L` 표시 절을 **지운다.** 빈 절을 남기지 않는다.
   `report.md` 는 L 이거나, 상태가 종료·보류로 바뀔 때 만든다.

5. **두 가지만 질문한다.** `1 문제와 배경`과 `6 성공 기준`은 사용자에게 물어야
   안다. 나머지는 `<!-- TODO -->`로 두고 진행 중에 채운다.

   성공 기준은 반드시 **숫자와 판정 방법**이 있어야 한다. 사용자가 "빨라지면
   좋겠다"처럼 답하면 현재값을 측정해서 목표 숫자를 제안하고 확인받는다.

   **잴 대상이 아직 없는 신규 프로젝트는 현재값을 `미측정`이라고 적는다.** 지어낸
   숫자를 넣지 않는다. 목표값과 판정 방법은 그래도 채운다.

   **`5 용어`는 `TODO`를 남기지 않는다.** 지금 확정된 것만 적고, 이름이 아직 없는
   용어는 이름 칸이 없는 표에 둔다.

6. **`2 해결 방법`을 쓸지 판정하고, 쓰기로 했으면 채운다.** 판정 질문은 하나다 —
   해결 방법을 이 프로젝트가 정하는가, 밖에서 받는가.

   | 이 프로젝트가 | 판정 |
   |---|---|
   | 해결 방법 자체를 내놓고 검증한다 (연구, 재현, PoC, 성능 개선) | 쓴다 |
   | 해결 방법이 밖에서 주어졌고 그걸 구현한다 (외주, 명세 구현, 이관) | 절을 지운다 |

   저장소만 보고 판단이 안 서면 그때만 `AskUserQuestion`으로 묻는다.

   쓰기로 했으면 1에서 규정한 문제의 어느 고리를 어디서 끊는지 쓰고, 각 단계를
   `7 기능 요구사항`의 `FR-nn`과 잇는다. 여기가 비면 문서가 문제 제기에서 끝나고,
   요약본이 원본보다 잘 읽히게 된다.

   지우기로 했으면 `1 문제와 배경` 끝에 명세의 출처를 한 줄 남기고, **지웠다는 사실과
   그 근거를 보고에 적는다.**

7. **`7 기능 요구사항`을 채운다.** `FR-nn` ID를 붙이고, 6에서 쓴 각 단계가 어느
   요구사항으로 이어지는지 맞춘다. 여기가 비면 사슬 B가 처음부터 끊긴 채로 시작한다.

8. **되돌리기 어려운 결정을 적는다.** 문제와 요구사항을 적은 다음이고, 코드를 쓰기
   전이다. 무엇이 되돌리기 어려운지는 이 프로젝트가 무엇을 하는지 알아야 고를 수 있다. 아래 다섯 축을 하나씩
   물어 이 프로젝트에 해당하는 것을 전부 고르고, `decisions/`에 파일을 하나씩 만든다.
   **개수 목표는 없다.** 해당 없는 축이 있으면 그렇게 보고하고 넘어간다. 숫자를
   채우려고 되돌리기 쉬운 결정을 끌어오면 결정층이 빈 파일로 찬다.

   | 축 | 묻는 것 |
   |---|---|
   | 도메인 경계 | 무엇과 무엇을 어디서 자르는가 |
   | 데이터 모델과 식별자 | 무엇을 키로 삼고 어떤 형태로 저장하는가 |
   | 일관성 모델 | 언제 상태를 바꾸고, 실패하면 무엇을 되돌리는가 |
   | 인증·인가 | 누가 무엇을 할 수 있는가 |
   | 외부 시스템과의 계약 | 무엇에 의존하고 그 계약이 바뀌면 어떻게 되는가 |

   | 지금 답이 | 파일 | 다음 |
   |---|---|---|
   | 나온다 | `상태: 유효` 로 채운다 | 그 위에 쌓는다 |
   | 안 나온다 | `상태: 미결` 로 두고 "정해질 때까지 미루는 것"만 채운다 | **그 영역을 건드리는 작업을 뒤로 미룬다** |

   되돌리기 쉬운 결정(클래스 이름, 패키지 구조 세부, 로깅 포맷)은 적지 않는다. 전부
   적으면 결정층이 잡음으로 찬다.

   미결로 두고 진행하면 그 결정을 에이전트가 대신 정하고, 그 선택은 코드 전체에 퍼진
   다음에 드러난다. 그래서 **미결 목록은 보고에 반드시 싣는다.**

9. **`design.md` 12 의 착수 순서를 채운다.** FR 을 무슨 순서로 할지와, 각각을
   **무엇으로 확인할지**를 같이 적는다. 순서는 걸리는 시간이 아니라 끝났을 때 맞는지
   짧게 확인할 수 있는가로 정한다. 확인 수단이 없는 항목은 그 수단을 먼저 만드는
   작업으로 쪼갠다. 첫 항목은 기능 하나를 입구부터 저장소까지 관통시키는 것으로 둔다.

10. **`<프로젝트 이름>`, 날짜, 프로파일을 실제 값으로 채우고 잔재를 지운다.**
   헤더의 프로파일 칸은 `M` 이나 `L` 한 글자만 남긴다. `생성 시 지침` 주석,
   `예시:` 주석, 제목의 `L` 표시, 안 채운 `YYYY-MM-DD`도 남기지 않는다.

   **`journal.md` 는 이 단계에서만 손댄다.** 세우는 시점에는 적을 일이 아직 없어서
   앞 단계가 이 파일을 건드리지 않는다. 제목을 채우고, 14 의 빈 `### YYYY-MM-DD` 절과
   "지난 기록" 의 링크 자리를 지운다. 첫 날짜 절은 `/doc-log` 가 만든다.

   ```bash
   grep -rn '<프로젝트 이름>\|생성 시 지침\|예시:\|path/to/file' <대상 디렉터리>/
   grep -rnE '^#{2,3} .*`L`' <대상 디렉터리>/
   ```

11. **프로젝트 `CLAUDE.md`가 없을 때만 갱신 규칙을 심는다.** 스킬은 불릴 때만
   로드되므로, 작업 중에 결정과 측정값이 어디로 가는지는 항상 로드되는 규칙 파일이
   붙들고 있어야 한다.

   | 프로젝트 루트에 `CLAUDE.md` 가 | 한다 |
   |---|---|
   | 없다 | 아래 내용으로 만든다 |
   | 있다 | **손대지 않는다.** 아래 네 줄을 보고에 그대로 싣고, 넣을지는 사용자가 정한다 |

   이미 있는 파일을 고치지 않는 이유는, 그 파일이 그 저장소의 모든 세션에 항상 로드되고
   저장소에 커밋되기 때문이다. 사용자가 일부러 다르게 써 둔 `## 문서` 절과 낡은 판을
   구분할 방법이 없어서, 병합하면 한 절 안에 모순된 지시가 남을 수 있다.

   전역 `~/.claude/CLAUDE.md` 는 어느 경우에도 건드리지 않는다.

   **`<대상 디렉터리>` 는 이 명령이 받은 `$1` 의 실제 값으로 바꿔 적는다.** `docs` 로
   박아두면 다른 디렉터리를 받았을 때 규칙이 없는 경로를 가리킨다.

   ```markdown
   ## 문서
   - 결정을 새로 정하거나 뒤집으면 `<대상 디렉터리>/decisions/` 에 파일을 추가한다
   - 측정값이 나오면 `<대상 디렉터리>/journal.md` 15 에 방법·명령어·값을 적는다
   - 요구사항·성공 기준이 바뀌면 `<대상 디렉터리>/charter.md` 를 고치고 16 에 남긴다
   - 세션을 끝낼 때 `/doc-log <대상 디렉터리>` 를 돌린다
   ```

12. **목차를 생성한다.**

   ```bash
   find <대상 디렉터리> -name '*.md' -not -path '*/journal/*' \
     -exec python3 <스킬 디렉터리>/scripts/gen-toc.py {} +
   ```

   템플릿의 `<!-- TOC -->` 자리에 h2/h3 목차가 들어간다. 손으로 쓰지 않는다.

13. **검증한다.**

   ```bash
   bash <스킬 디렉터리>/scripts/check-trace.sh <대상 디렉터리>
   ```

   갓 만든 문서는 사슬이 끊겨 있는 게 정상이고 종료 코드 1 이 나온다. 출력을 그대로
   보여주고 "이 항목들이 진행하면서 채워질 자리"라고 설명한다. 종료 코드가 9 면
   경로가 틀렸거나 `charter.md` 가 없는 것이니 그때는 고친다.

## 보고

3. 사용자가 답한 `1`, `6` 요약. `2` 해결 방법은 채웠으면 요약을, 지웠으면 그 근거를
4. **되돌리기 어려운 결정 목록 — 정한 것과 `미결`로 남은 것.** 미결 각각에 대해
   그것 때문에 미루는 작업을 한 줄로 적는다
5. `CLAUDE.md` — 만들었으면 넣은 줄, 이미 있었으면 손대지 않았다는 사실과 제안 네 줄
6. `check-trace.sh` 출력과 종료 코드

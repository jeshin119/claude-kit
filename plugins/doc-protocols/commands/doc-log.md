`project-doc-framework` 스킬을 불러 **갱신 절차**를 따른다. 대상 디렉터리는
`$1`이고, 비어 있으면 `docs`다.

`docs/journal.md`가 없으면 여기서 멈추고 `/doc-init`을 먼저 돌리라고 알린다.

## 순서

1. **이번 세션에서 실제로 무엇이 바뀌었는지 확인한다.**

   ```bash
   git status --short && git log --oneline -20 && git diff --stat
   ```

   대화 기억만으로 적지 않는다. 파일 변경을 근거로 삼는다.

2. **14 작업 로그에 붙인다.** 오늘 날짜 절이 이미 있으면 **그 절에 이어 붙인다.**
   새 절을 만들지 않는다.

   - 한 일: 결과만. 시도 과정은 막힌 것 표에 넣는다
   - 막힌 것: 증상 / 원인 / 해결. **원인 칸이 비면 아직 안 풀린 것이니 그렇게 적는다**
   - **버린 접근: 시도했다가 접은 것과 접은 이유.** 이번 세션에서 방향을 한 번이라도
     바꿨으면 반드시 적는다. 컨텍스트가 압축되면 한 일은 남고 버린 접근은 사라져서,
     다음 세션이 그걸 다시 꺼낸다. 버린 이유가 설계 판단이면 `decisions/` 에 옮긴다
   - 잘 굴러간 작업의 상세는 적지 않는다

3. **15 검증 기록에 붙인다.** 이번 세션에서 명령어를 돌려 값을 얻었으면 날짜, 대상
   `SC-nn`/`FR-nn`, 방법, 명령어, 실측값을 적는다.
   **판정하지 않는다.** "통과"·"잘 됨"이 아니라 값을 적는다.
   측정한 게 없으면 이 항목은 건드리지 않는다.

   `방법` 칸은 `타입·컴파일` / `테스트(스펙 확인)` / `테스트(미확인)` / `실행` /
   `정적분석` / `LLM 검토` 중 하나다. **이번 세션이 테스트를 쓰고 이번 세션이
   구현했으면 `테스트(미확인)` 이다.** 사람이 스펙을 확인했는지가 갈림길이고, 통과
   여부가 아니다. 이번 세션이 스스로 코드를 훑어본 것은 검증이 아니라 적지 않는다.

4. **계약이 바뀌었으면 16에 적는다.** 절은 번호가 아니라 이름으로 적는다. 요구사항이나 성공 기준을 이번에 고쳤을
   때만이다. 코드 변경은 적지 않는다.

5. **롤오버를 확인한다.** `journal.md`의 14에 지난 달 날짜 절이 있으면
   `journal/YYYY-MM.md`로 옮기고 상단 "지난 기록"에 링크를 추가한다.

   **15도 같이 옮긴다.** 지난 달 날짜의 행을 같은 아카이브 파일로 옮기되,
   **각 ID(`SC-nn`/`FR-nn`)의 가장 최근 한 줄은 `journal.md`에 남긴다.**
   남기는 줄은 날짜가 지난 달이어도 옮기지 않는다. 아카이브에는 그 줄의 사본을
   같이 넣어 그 달의 추이가 온전하게 한다.

   **롤오버 직후에** 남은 15의 행 수가 `charter.md`의 SC + FR 개수를 넘으면 안 된다.
   넘으면 같은 ID가 두 줄 남은 것이니 오래된 쪽을 옮긴다. 같은 달 안에서 한 ID를
   여러 번 재서 행이 쌓이는 것은 정상이고, 여기 걸리지 않는다.

   16은 옮기지 않는다.

6. **다른 층을 건드렸는지 점검한다.** 이번 세션에서 아키텍처나 구현이 바뀌었으면
   `design.md`도 갱신해야 한다. 대신 고치지 말고 **무엇이 낡았는지 보고한다.**
   결정을 뒤집었으면 `decisions/`에 새 파일이 필요하다고 알린다.
   `decisions/`에 `상태: 미결`인 파일이 있고 이번 세션이 그 영역을 건드렸으면,
   그 결정이 아직 미결이라는 사실을 보고에 올린다.

7. **일이 멈췄으면 종결 절차로 넘어간다.** 사용자가 종료나 보류를 말했거나 마지막
   기록으로부터 시간이 크게 벌어졌으면, `charter.md` 헤더의 `상태`를 바꾸고
   `report.md`를 만들자고 제안한다. 프로파일 M 도 만든다. 절차는 스킬의
   **종결·보류**를 따른다. 사용자가 진행 중이라고 하면 그대로 둔다.

8. **검증한다.**

   ```bash
   bash <스킬 디렉터리>/scripts/check-trace.sh <대상 디렉터리>
   ```

   종료 코드로 무엇이 걸렸는지 구분한다. `1` 은 사슬이나 ADR 참조, `2` 는 승급 신호,
   `3` 은 둘 다, `9` 는 실행 오류다.

## 보고

1. 붙인 항목 — 14 / 15 / 16 각각 몇 줄. 버린 접근을 적었으면 그것도
2. 롤오버 여부
3. 낡았을 가능성이 있는 다른 층 (`design.md`, `decisions/`)과 미결로 남은 결정
4. `check-trace.sh` 의 진척 세 줄과 이번에 달라진 부분
5. 승급 신호나 종결 제안이 있으면 — 어떻게 할지, 안 한다면 그 이유

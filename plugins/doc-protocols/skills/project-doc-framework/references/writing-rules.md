# 문서 문체·구조 규칙

프레임워크의 어느 층을 쓰든 이 규칙을 적용한다. 이미 있는 문서를 정리할 때는 맨 끝의
절차를 그대로 따른다.

## 문체

| 규칙 | 적용 |
|---|---|
| 검증 가능한 서술 | `~할 수 있어야 한다`, `~해야 한다`, `~하지 않는다`로 끝낸다 |
| 주체 명시 | `사용자는 ~할 수 있어야 한다` / `시스템은 ~해야 한다` |
| 하지 않아도 되는 것 | 사용자가 판단하거나 조작하지 않아도 되는 지점을 명시한다 |
| 감정 표현 제거 | 귀찮다, 어렵다, 번거롭다, 죽는다, 당했다, 무방비, 헛되이 |
| 구어 어미 제거 | `~거든요`, `~해요`, `~에요`. 문두 접속사(그래서, 하지만, 다만, 따라서)는 문장 관계를 밝히는 데 쓰되 같은 것을 문단마다 반복하지 않는다 |
| 소제목은 명사형 | "어디서 실행할 것인가" → "실행 위치" |
| 반복 제거 | 구체 항목은 나열하되 같은 말을 절마다 되풀이하지 않는다 |

구성 순서는 사용자 행동, 시스템 행동, 기대 효과다.

### 격식 유지

문서는 보고서 문체(`~한다`, `~이다`)로 쓴다. 문체가 보고서인데 어휘가 구어면 읽는
쪽은 문장마다 격식을 다시 맞춰야 한다. 아래 왼쪽은 대화에서는 자연스럽지만 문서에서는
오른쪽으로 바꾼다.

| 구어 | 문서 |
|---|---|
| 스크립트가 돈다 / 훅이 돈다 | 스크립트가 실행된다 / 훅이 동작한다 |
| 설정이 먹는다 | 설정이 적용된다 |
| 플러그인을 깐다 | 플러그인을 설치한다 |
| 알림이 뜬다 / 목록에 뜬다 | 알림이 표시된다 / 목록에 나타난다 |
| 검사에 걸린다 | 검사에서 검출된다 / 조건에 해당한다 |
| 절차를 부른다 | 절차를 실행한다 / 스킬을 호출한다 |
| 오류를 잡는다 | 오류를 검출한다 |
| 파일을 손댄다 / 건드린다 | 파일을 수정한다 |
| 코드를 친다 | 코드를 작성한다 |
| 내용이 날아간다 | 내용이 지워진다 |
| 사본이 갈라진다 | 사본이 원본과 달라진다 |
| 문서가 낡았다 | 문서가 최신이 아니다 |
| 통째로 갈아엎는다 | 전부 교체한다 |
| 막힌 것을 뚫었다 | 막힌 것을 해결했다 |

### 무생물 주어

사물을 사람처럼 움직이는 주어로 쓰지 않는다. 영어 문장을 그대로 옮길 때 나오는
형태라, 영어 초안을 거친 문서에 특히 많이 남는다.

| 고치는 법 | 적용 |
|---|---|
| 주어 교체 | 그 동작을 실제로 하는 사람이나 행위를 주어 자리에 올린다 |
| 수단으로 내리기 | 사물은 `~에서`, `~를 쓰면`으로 내리고 주어 자리를 비운다 |
| 삭제 | 앞 문장을 비유로 한 번 더 말하는 문장이면 지운다 |

| before | after |
|---|---|
| 사슬 B가 그걸 자동으로 잡아낸다 | 그것은 사슬 B에서 자동으로 검출된다 |
| 틀린 문장이 조용히 들어온다 | 틀린 문장이 눈에 띄지 않게 섞인다 |
| organizer는 이미 본문을 다듬는다 | 본문 다듬기는 이미 organizer가 한다 |
| 게이트웨이는 에이전트와 도구 사이에 앉아 있다 | 게이트웨이는 에이전트와 도구 사이에 있다 |
| 시계는 이미 돌기 시작했다 | (삭제) |

`시스템은 ~해야 한다`는 여기 해당하지 않는다. 계약 문장의 주어는 책임 주체를
가리키므로 위 "주체 명시"와 충돌하지 않는다. 금지 대상은 사물이 사람의 동작(잡아낸다,
앉아 있다, 노력한다, 알고 있다, 기다린다)을 하는 문장이다.

### 비유

영어 관용구를 옮긴 비유를 쓰지 않는다. 비유가 대신한 사실이 문장에서 사라지고 읽는
쪽은 원래 표현을 되짚어야 뜻을 알 수 있으므로, 비유는 설명을 줄여 주지 않는다.
비유를 지우고 그 자리에 사실을 쓴다.

| before | after |
|---|---|
| 공격자가 조종권을 쥔 채로 열린 마이크를 받는다 | 공격자가 정한 내용이 그대로 밖으로 나간다 |
| 시계가 도는 쪽 | 기한이 걸린 쪽 |
| 흔한 출력은 그대로 나오고 꼬리 쪽 확률만 재배치된다 | 자주 나오는 출력은 그대로고 드물게 나오는 쪽 확률만 바뀐다 |
| 우회는 타당하지만 그 대가가 남는다 | 우회는 타당하지만 재현성을 포기해야 한다 |
| ADR에 안 산 재료를 넣었다 | ADR에 실제로 쓰지 않은 근거를 적었다 |
| 검증 속도가 프로젝트의 상한이 된다 | 프로젝트의 진행 속도는 검증 속도에 따라 정해진다 |
| 확인하지 않은 코드는 자산이 아니라 부채다 | 확인하지 않은 코드는 남겨 둘수록 고치는 비용이 커진다 |
| 그것은 목적이 아니라 바람이다 | 그것은 달성 여부를 판정할 수 없는 목표다 |
| 결정층이 잡음으로 찬다 | 중요하지 않은 결정에 중요한 결정이 묻힌다 |
| 기능 하나를 입구부터 저장소까지 관통시킨다 | 기능 하나를 입구부터 저장소까지 끝까지 구현한다 |

### 문장 마무리

한 문장 안에서 결론까지 쓰고, 다음 문장에서 밝히려고 앞 문장을 비워 두지 않는다.
절 전체의 서술 순서는 별개로, 1 문제와 배경의 순서는 아래 "읽히는 배경"을 따른다.

명사구로 문장을 닫지 않는다. `A가 아니라 B다` 형태의 대조 강조는 두 문장으로 나눈다.

| before | after |
|---|---|
| 이 값을 유지한 이유는 다르다 | 이 값을 유지한 이유는 태그가 그 커밋을 가리키고 있어서다 |
| 이 프로젝트가 새로 제안하는 개념은 없다 | 이 프로젝트는 기존 A와 B를 C에 적용한다 |
| 권장 사항은 A로 걸러내고 남으면 B다 | A로 먼저 걸러내고, 남은 것만 B로 검증한다 |
| 틀린 것은 인과지 값이 아니다 | 값은 맞다. 원인 설명이 틀렸다 |

성과를 미리 깎는 문장을 쓰지 않는다. 무엇이 없는지가 아니라 무엇을 했는지를 적는다.

"이를 통해 ~할 수 있도록 한다"로 절을 닫지 않는다. 앞 문장들이 이미 말한 효과를
한 번 더 요약하는 마무리 문장이다. 효과가 따로 있으면 그 사실을 쓰고, 없으면 지운다.

### 문장을 끊는 단위

한 번에 말할 수 있는 것은 한 문장으로 쓴다. 짧은 문장을 연달아 놓으면 강조하는
것처럼 읽히고, 앞 문장과 뒤 문장의 관계(이유인지, 조건인지, 대조인지)를 읽는 쪽이
채워야 한다. 관계가 있으면 연결어미(`~므로`, `~는데`, `~고`, `~며`)로 잇고, 없으면
그때 나눈다.

기준은 한국어 설명문의 보통 길이다. 기사는 문장당 25~45어절, 기술 블로그는 10~15어절
단문과 25~35어절 설명문을 섞는다. 6어절 이하 문장이 연달아 나오면 합칠 곳이다.
문단을 여는 주제 문장 하나는 짧아도 된다.

| before | after |
|---|---|
| 값만 적는다. 판정하지 않는다. | 값만 적고 판정은 하지 않는다. |
| M 아래는 두지 않는다. 하루짜리 작업이라도 문제와 성공 기준을 안 적으면 남는 것이 없다. | M보다 작은 프로파일은 두지 않는다. 하루짜리 작업이라도 문제와 성공 기준을 적지 않으면 남는 것이 없기 때문이다. |
| 층이 곧 파일 경계다. | 층은 파일을 나누는 기준으로, 층마다 파일 하나가 있고 갱신 방식도 층마다 다르다. |
| 세 표면 모두 수동으로 갱신해야 한다. 저장소를 고쳐도 자동으로 퍼지지 않는다. | 저장소를 고쳐도 자동으로 퍼지지 않으므로 세 표면 모두 수동으로 갱신해야 한다. |
| ID는 재사용하지 않는다. 항목을 지워도 번호는 비워 둔다. | 항목을 지워도 그 번호는 비워 두고 재사용하지 않는다. |

굵은 글자 뒤에 줄표(—)를 붙여 문장을 이어가지 않는다. 굵은 부분은 제목처럼 읽히는데
뒤가 문장이라 어디까지가 제목인지 알 수 없다. 완결된 문장으로 쓰거나 h3 제목으로
올린다.

| before | after |
|---|---|
| **승급 신호** — 하나라도 걸리면 M에서 L로 올린다. | M에서 L로 올리는 것을 승급이라 한다. 다음 세 신호 중 하나라도 해당하면 승급한다. |
| **번호는 고정이다.** 프로파일이 올라가도 ... | 번호는 고정이다. 프로파일이 올라가도 ... |

### 제목

제목은 그 절의 내용을 말하는 명사구로 쓴다. 영어 제목(What it solves, Why keep it)을
의문문으로 옮기지 않는다. 의문문 제목은 답이 본문 어디에 있는지 읽는 쪽이 찾아야
한다. 기사·논문·보고서는 명사구 제목만 쓰고, 기술 블로그 같은 이야기체만 "왜
SSE였나" 같은 의문형 소제목을 쓴다. 프로젝트 문서는 참조 문서이므로 명사구다.

| before | after |
|---|---|
| 무엇을 푸는가 | 해결하려는 문제 |
| 왜 남기는가 | 문서를 남겨야 하는 이유 |
| 왜 나눠 두는가 | 파일을 나누는 이유 |
| 언제 쓰는가 | 사용 시점 |
| 목적이 바람이 아님을 증명한다 | 성공 기준이 달성됐는지 확인한다 |

### 어휘

| before | after |
|---|---|
| `updated_at`이 실행보다 앞선다 | `updated_at`이 실행보다 이르다 |
| 낡은 브랜치 | 사용하지 않는 브랜치 |
| `report.md`에 한 줄 박아둔다 | `report.md`에 한 줄 적어둔다 |
| 지표를 1h로 내려온다 | 지표를 1h로 내린다 |
| 롤오버, 스코프 | 월별 보관, 범위 |
| 세우기 (setup의 역어) | 생성 |
| 자기 신고 (self-report의 역어) | 적는 쪽이 스스로 고르는 값 |

동사를 명사로 굳혀 용어처럼 쓰지 않는다. "세우기", "붙이기", "되돌리기 어려움"처럼
영어 동명사를 옮긴 이름은 한국어에서 용어로 자리 잡지 못한다. 절차 이름은 한자어
명사(생성, 갱신, 정리, 종결)로 쓴다.

### 조사 붙여쓰기

코드 표기, 숫자, 영문 뒤에 오는 조사도 붙여 쓴다. `charter.md` 를, 15 의, M 에서처럼
띄우면 읽는 속도가 떨어지고 검색에도 걸리지 않는다.

| before | after |
|---|---|
| `charter.md` 를 고친다 | `charter.md`를 고친다 |
| 15 의 방법 칸 | 15 검증 기록의 방법 칸 |
| M 에서 L 로 | M에서 L로 |
| 사슬 B 가 | 사슬 B가 |

### 항목 번호 표기

항목 번호는 항상 항목 이름과 함께 쓴다. "12와 15가 비어 있다"라고 쓰면 읽는 쪽이 번호
표를 다시 찾아야 한다. 같은 문단 안에서 반복될 때만 두 번째부터 번호를 생략할 수 있다.

| before | after |
|---|---|
| 12와 15가 비어 있으므로 1이 정상이다 | 12 구현 현황과 15 검증 기록이 비어 있으므로 종료 코드 1이 정상이다 |
| 10에 `상태: 미결` | 10 결정 기록에 `상태: 미결`로 |
| 17 판정이 최신 실측값을 봐야 한다 | 17 결과와 한계의 판정이 최신 실측값을 봐야 한다 |

프레임워크가 정한 이름(층, 사슬, 프로파일, 승급)은 문서마다 첫 등장에서 한 줄로
정의한다. 다른 문서에서 정의했다는 이유로 생략하지 않는다.

### 층별 예외

| 층 | 문체 |
|---|---|
| 1 문제와 배경 | 서술체. 아래 "읽히는 배경" 참조. 요구사항체로 쓰지 않는다 |
| 2 해결 방법 | 현재형 평서문 `~한다`. 1의 서술체와 7의 요구사항체 사이다. 표와 서술을 섞어 쓴다 |
| 정의·계약 (3~9) | 위 규칙 전면 적용. 요구사항은 `~해야 한다`로 끝낸다 |
| 결정 (10) | 서술체 허용. 왜 그렇게 판단했는지가 본문이라 단정문만으로는 쓸 수 없다 |
| 현행 (11~13) | 현재형 평서문 `~한다`. 요구사항체를 쓰지 않는다 |
| 기록 (14~16) | 과거형 사실 기록 `~했다`, `~였다`. 판단과 사실을 섞지 않는다 |
| 종결 (17~19) | 판정문. `달성`, `미달`, `해당 없음`을 명시한다 |

### 읽히는 배경 (1 문제와 배경 전용)

대상 분야를 모르는 사람이 읽고 따라올 수 있어야 한다. 이 절이 읽히지 않으면 나머지
18개 항목이 무엇을 위한 것인지 알 수 없다.

| 규칙 | 적용 |
|---|---|
| 순서 | 상황, 사례, 원인 순서다. 결론을 첫 문장에 두지 않는다 |
| 사례 우선 | 추상적 원인 서술 앞에 실제로 일어난 일 한 건을 놓는다. 단계가 여럿이면 번호 목록으로 편다 |
| 분할 | 절이 화면 하나를 넘으면 h3로 나눈다. h3 제목이 곧 요약이 되게 쓴다 |
| 결론문 연속 금지 | 단정문만 이어지면 근거 없는 주장으로 읽힌다. 각 결론에 그 근거를 붙인다 |
| 해결 분리 | "어떻게 푸는가"는 여기 쓰지 않고 2 해결 방법으로 넘긴다. 2를 만들지 않는 프로젝트만 예외로 명세 출처 한 줄을 여기 남긴다 |

### 용어 표기와 초출 정의

바깥에서 온 이름(API 이름, 필드명, 도구 이름, 업계 용어)은 원어를 그대로 쓴다.
번역하거나 줄이면 독자가 원문에서 그 이름을 찾을 수 없다.

용어는 처음 나오는 자리에서 한 문장으로 설명한다. 용어 표(5)에 있다는 이유로 본문
설명을 생략하지 않는다. 표는 다시 찾아보는 곳이지 처음 배우는 곳이 아니다. 널리
통용되는 용어도 독자가 그 분야 밖에서 오므로 문서에서는 초출 정의를 생략하지
않는다. 짧은 고유어 동사(재다·새다·성기다)로 추상 개념을 반복해서 가리키지 않는다.
개념은 명사로 한 번 정하고 그 뒤로는 그 명사를 쓴다.

| 종류 | 처리 |
|---|---|
| 도메인 전문 용어 (`taint`, `egress`, `declassification`) | 초출 위치에서 한 문장 정의. 그 뒤 `(5 용어)`로 연결 |
| 고유명사·사건명 (`GitLost`, `CaMeL`) | 누가 언제 무엇에 붙인 이름인지 먼저 밝힌다 |
| 약어 (`MCP`, `ASR`, `FBR`) | 초출에 원어를 병기하고, 5 용어의 약어 표에도 빠짐없이 넣는다 |
| 번역이 어색한 학술 용어 (`적대자`, `단조 증가`) | 뜻이 통하는 일상어로 바꾼다. `공격자`, `한 번 붙으면 풀리지 않는다` |
| 한국어에 없는 조어 (`과대근사`, `무진전`) | 만들지 않는다. 뜻을 풀어 쓴다. `일부러 실제보다 넓게 잡은 값` |
| 역어와 원어가 갈리는 용어 (`멱등성`/`idempotency`) | 실제로 더 많이 쓰이는 쪽을 쓴다. 역어가 있어도 원어가 통용되면 원어 |
| 원어 음차·임의 축약 (`스핀`, `스모크 스크립트`) | 굳은 용어면 원어를 그대로 쓰고 한 문장으로 설명한다. `smoke test`. 굳은 용어가 아니면 뜻을 풀어 쓴다. `진척 없이 제자리를 도는 상태` |

### 프레임워크 용어 비노출

층 이름(정의층·계약층·결정층·현행층·기록층·종결층)을 프로젝트 문서 본문에 쓰지
않는다. 층은 파일을 나누는 기준이지 독자가 알아야 할 개념이 아니다. 갱신
규칙("덮어쓴다", "붙이기만 한다")과 도구 이름(`archify`, `gen-toc.py`)도 문서를 쓰는
쪽을 향한 지시이므로 본문에 두지 않는다. 템플릿에서는 그런 지시를 `생성 시 지침`
주석에 두고 생성 후 지운다.

파일 상단에는 그 자리에 독자용 안내 한 문단을 둔다. 이 문서에 무엇이 있고, 여기
없는 것은 어디에 있는지를 적는다.

### 보정 예시

before

> 기록을 남기는 데는 두 가지 일이 섞여 있어요. 적는 일과 정리하는 일이요.
> 적는 건 쉬워요. 정리는 어려워요. 제목을 뭐라고 할지, 태그를 뭘 달지를 그 순간에
> 정해야 하거든요. 이게 귀찮아서 사람들은 정리를 포기하거나 아예 안 적어요.
> 그래서 순서를 바꿔요. 적을 때는 아무것도 정하지 않고, 정리는 나중에 도구가 해요.

after

> **기록과 정리를 분리한다.**
>
> - `FR-01` 사용자는 내용을 알게 된 즉시 별도의 분류나 정리 없이 기록할 수 있어야 한다.
> - `FR-02` 기록 시 제목, 분야, 태그, 기존 노트와의 연관 관계를 사용자가 직접
>   판단하지 않아도 되어야 한다.
> - `FR-03` 분류, 태그 지정, 기존 노트와의 연결은 이후 도구가 수행한다.
>
> 기록하는 시점에 사용자가 판단할 것이 없으므로 내용만 적으면 된다.

## 제거 검토

**제거 후보**

- 첫 줄이 "N장과 같다"로 시작하는 절. 참조 대상에 통합하고 절을 삭제한다
- 해소된 미결·초안 잔재. 본문에 이미 반영됐다면 목록에서 뺀다
- 채택하지 않은 설계에만 존재하던 위험·제약 메모
- 요구사항도 제약도 아닌 기록 (명명 후보 검토, 잡담성 부록)
- 장 구성 안내 문단. 목차를 넣으면 대체된다
- 같은 사실을 반복하는 도입 문단
- 다른 층에 이미 있는 내용의 사본. 원본 층에 두고 참조로 바꾼다

**제거하면 안 되는 것**

- 다른 절이 `근거는 ADR-nnnn`으로 참조하는 항목. 빼면 "왜"에 답이 없어진다
- 결론이 "불가능"·"해당 없음"뿐이어도 범위를 지키는 역할을 하는 항목
- 탈락한 대안 안에 섞여 있는, 현행 설계가 의존하는 실측 근거
- 수치·명령어·출력 등 검증 기록
- 결정층(10)의 항목 전부. 결정 기록은 지우지 않고 `상태: 폐기`로 표시한다
- 14 작업 로그의 버린 접근. 지우면 다음 세션이 그 접근을 다시 시도한다
- `상태: 미결`인 결정. 답이 없다는 사실이 정보다

판단 기준은 하나로, 지우기 전에 그 항목을 참조하는 곳이 있는지 먼저 grep한다.

## 구조

- **목차**: h2/h3 전체를 앵커 링크로 만들어 헤더 메타 블록 바로 아래에 둔다. 모든
  파일에 두되, 지난달 기록은 훑어보는 자리라 `journal/YYYY-MM.md`에는 만들지 않는다
- **앵커 생성**: 손으로 쓰지 않고 `scripts/gen-toc.py`로 생성한다. 파일에
  `<!-- TOC -->` 한 줄을 두면 그 자리에 목차를 채우고, 이미 있으면 갱신한다

  ```bash
  find docs -name '*.md' -not -path '*/journal/*' \
    -exec python3 <스킬 디렉터리>/scripts/gen-toc.py {} +
  ```

  앵커는 소문자화, 링크·강조·백틱 제거, 문자·숫자·공백·하이픈 외 제거, 공백을
  하이픈으로 치환하는 순서로 만들며 GitHub의 앵커 생성과 같다. 목차를 손으로 쓰면
  em dash·괄호·마침표가 든 제목에서 앵커가 어긋난다
- **교차 참조**: 다른 파일의 절을 가리킬 때는 `charter.md` 6 성공 기준처럼 파일명과
  항목 이름을 붙인다. 번호만 쓰면 어느 파일의 몇 번인지 알 수 없다. 절을 옮기거나
  지우면 항목 번호와 ID 참조를 전부 갱신한다. 갱신 대상은 `docs/` 안뿐 아니라 README
  등 요약본까지다
- **항목 번호 신설 금지**: 프로젝트 문서에 새 최상위 항목 번호를 만들지 않는다. 쓸
  자리가 없으면 기존 항목 안에 h3로 넣는다. 번호를 늘리면 다른 항목과 겹치고, 쌓기만
  하는 기록층의 과거 행이 전부 틀리게 된다
- **번호 정합**: 헤더의 "미결 N건"과 실제 표 행 수처럼 서로 맞아야 하는 값을 대조한다
- **층 경계 유지**: 편집 중에 다른 층의 내용이 흘러들어오면 원래 층으로 옮긴다

## 절차

1. 파일 전체를 읽는다. 부분만 보고 고치지 않는다
2. 원본을 스크래치패드에 백업한다
3. 문체, 제거, 구조 순서로 진행한다
4. 스크립트로 편집할 때는 치환 전 `assert count == 1`로 대상이 하나뿐인지 확인한다
5. 검증 grep을 실행한다

```bash
grep -nE '정의층|계약층|결정층|현행층|기록층|종결층' FILE   # 프레임워크 용어 노출
grep -L '<!-- TOC -->' FILE                                # 목차 누락
grep -n '<지운 항목 번호>\|<지운 항목 제목>' FILE   # 끊긴 참조 확인
grep -nE '` (를|을|가|이|은|는|의|에|로|으로|와|과|도) ' FILE   # 코드 표기 뒤 조사 띄어쓰기
grep -nE '^#{2,3} .*(는가|은가|인가)\??$' FILE            # 의문문 제목
```

문장 길이는 아래로 잰다. 6어절 이하 문장이 전체의 20%를 넘으면 합칠 곳이 남은 것이다.

```bash
python3 -c "
import re,sys,statistics
s=re.sub(r'\x60\x60\x60.*?\x60\x60\x60','',open(sys.argv[1]).read(),flags=re.S)
b=' '.join(l for l in s.split('\n') if l and not l.startswith(('#','|','-','<')))
n=[len(x.split()) for x in re.split(r'(?<=다\.)\s',b) if x.strip()]
print('문장',len(n),'평균 어절',round(statistics.mean(n),1),'6어절 이하',sum(1 for k in n if k<=6))
" FILE
```

# 개인 상시 지시사항

이 파일은 `~/.claude/CLAUDE.md`로 심링크되어 **모든 세션에 무조건 로딩된다.**
스킬과 달리 발동 조건이 없다. 항상 참인 것만 넣는다. 특정 작업에서만 필요한
절차는 스킬로 분리한다.

## 실행 환경

- Windows 호스트, 실제 작업은 전부 WSL2 안에서 이루어진다.
- 저장소는 WSL 파일시스템(`~/...`)에 둔다. `/mnt/c/...`는 느리고 파일 감시가
  깨진다.
- Docker는 아직 쓰지 않지만 도입 예정이다. 저장소 밖 절대경로를 쓰지 않고,
  홈 디렉터리에 대해 `$HOME` 외의 가정을 하지 않는다.

## 스킬과의 경계

- `humanize-korean`은 **다 쓴 뒤에** 문체를 다듬는다.
- 아래 번역투 지침은 **쓰는 중에** 문체를 규정한다.
- 두 규칙이 겹치면 출력이 오락가락하므로, 이 경계를 유지한다.

# 한국어 번역투 지침

## 0. 목적
영어 문장을 그대로 옮긴 듯한 한국어를 한국어 문장으로 되돌린다.
말투와 격식은 다루지 않는다. 문장 구조만 본다.
의미와 사실, 숫자는 그대로 둔다.

단어 하나만 보고 고치지 않는다. 아래 신호가 한 문장에 두 개 이상
겹칠 때 그 문장을 다시 쓴다.

## 1. 신호

### 주어와 태
- 무생물이 주어다: `조사는 ~을 보여준다`, `이 결과는 ~을 시사한다`
- 주체가 지워진 피동·가능형: `저장됩니다`, `변경이 가능하며`, `~에 의해`
- 사동·허용 구문(allows you to): `~할 수 있게 해줍니다`, `~하도록 도와줍니다`

### 명사로 뭉친 구조
- 명사가 명사를 물고 있다: `~성`, `~화`, `~을 위한`, `제공`, `실시`, `가능`
- 명사 앞에 관형절이 두 겹 넘게 쌓인다:
  `사용자가 입력한 데이터를 기반으로 생성된 결과를 저장하는 기능`

### 영어 구문 직역
- 번역투 조사구: `~에 있어서`(in terms of), `~의 경우`(in the case of),
  `~에 대하여`(regarding), `~로 인하여`(due to), `~에 의하여`(by)
- 영어 동사를 그대로 옮겼다: `~를 가지고 있다`(have),
  `~하지 않으면 안 된다`(must), `~되어지다`
- 만능 동사: `~로 이어집니다`(leads to), `~에 기여합니다`(contributes to)
- 부정으로 정의한다(It's not X, it's Y): `단순한 X가 아니라 Y입니다`
- 책임을 미루는 서술(it can be said that): `~라고 할 수 있습니다`,
  `~로 볼 수 있습니다`, `~로 평가됩니다`
- 완충이 겹친다: `상당히 긍정적인 영향을 줄 수 있을 것으로 보입니다`

### 연결어와 수식어
- 관계를 설명하는 척하는 연결어: `또한`(moreover), `이를 통해`(through this),
  `이를 기반으로`(based on this), `결론적으로`(in conclusion)
- -ly 부사를 그대로 옮긴다: `효과적으로`(effectively), `성공적으로`(successfully),
  `체계적으로`, `전략적으로`
- 영어 형용사 채움말: `다양한`(various), `핵심`(key), `필수`(essential), `폭넓은`

### 영어에는 있고 한국어에는 없는 것
- 대명사와 지시어를 되살린다: `이는 ~을 의미합니다`, `그것은`, `이러한`.
  한국어는 앞 문장에서 이어지면 주어를 생략한다.
- 복수 `~들`을 영어 -s만큼 붙인다: `사용자들이 파일들을 업로드합니다`
- 같은 대상을 동의어로 돌려 부른다: 사용자 → 고객 → 이용자.
  영어는 같은 단어 반복을 피하지만 한국어는 그냥 반복한다.

## 2. 고치는 방향
명사를 동사로. 피동을 능동으로. 무생물 주어는 사람이나 동작 주체로 바꾸거나 지운다.
겹친 관형절은 시간 순서대로 푼다. 번역투 조사구는 한국어 조사로 돌린다.
회피형 서술은 그냥 단언한다. 채움말은 지우거나 구체적 사실로 바꾼다.

주장의 강도는 근거에 맞춘다. 근거가 있으면 "줄인다",
없으면 "줄어들 수 있다". 습관적으로 약하게 말하지 않는다.

점검은 이 순서로 한다.
1. 주어를 본다. 무생물이면 주체를 밝히거나 지운다.
2. 명사로 뭉친 자리를 동사로 푼다.
3. 채움말과 -ly 부사를 지운다. 지우고 뜻이 안 변하면 없어도 되는 말이다.
4. 대명사, 지시어, `~들`을 지운다. 지우고도 읽히면 지운 채로 둔다.

## 3. 하지 말 것
- 위 표현을 금지어로 취급해서 기계적으로 치환하지 않는다.
  "또한 그는 이 문제를 지적했다"는 멀쩡한 문장이다. 신호가 겹칠 때만 손댄다.
- 자연스럽게 만들려고 사실이나 숫자를 바꾸지 않는다.
- 군더더기를 빼라는 뜻이지 내용을 빼라는 뜻이 아니다. 필요한 내용은 다 담는다.

## 4. 예외
1. 사용자가 문체를 직접 지정하면 그 지시를 따른다.
2. 기존 문서를 이어 쓰거나 고칠 때는 원문의 문체를 따른다.
3. 계약서, 법률 문서, 코드, 영문 산출물은 해당 형식을 따른다.
4. 인용문은 원문 그대로 둔다. 원문과 대조하는 번역도 그대로 둔다.

## 5. 예시
종결어미는 보지 않는다. 문장 구조만 본다.

Before: 반복 업무 효율성 향상을 위한 자동화 기능 제공이 가능합니다.
After:  반복 업무를 자동으로 처리해서 시간을 줄입니다.
Why:    명사가 여섯 개 이어져 있고 누가 뭘 하는지가 안 보인다.

Before: 설정 변경이 가능하며 결과는 자동으로 저장됩니다.
After:  설정을 바꾸면 시스템이 결과를 자동으로 저장합니다.
Why:    주체가 지워져 있다. 누가 저장하는지 밝힌다.

Before: 이 기능은 사용자가 반복 작업을 자동으로 처리할 수 있게 해줍니다.
After:  이 기능이 반복 작업을 자동으로 처리합니다.
Why:    allows you to를 그대로 옮긴 사동 구문. 주어를 기능으로 놓으면 사라진다.

Before: 사용자가 입력한 데이터를 기반으로 생성된 결과를 저장하는 기능입니다.
After:  사용자가 데이터를 넣으면 결과를 만들어서 저장합니다.
Why:    명사 하나 앞에 관형절이 세 겹. 시간 순서대로 풀면 된다.

Before: 이 조사는 우리에게 응답자의 64%가 모바일 결제를 선호한다는 것을 보여준다.
After:  이 조사에 따르면 응답자의 64%가 모바일 결제를 선호한다.
Why:    무생물 주어에 '~을 보여준다'. 영어 구문을 그대로 옮긴 것이다.

Before: 이 기능은 캐시를 사용합니다. 이는 응답 속도를 향상시킵니다.
After:  이 기능은 캐시를 써서 응답이 빨라집니다.
Why:    which improves의 관계대명사를 지시어로 살려 옮긴 것. 붙이면 된다.

Before: 또한 이를 통해 사용자는 필요한 정보를 더 빠르게 찾고 헤매는 시간을 줄일 수 있습니다.
After:  사용자는 필요한 정보를 더 빨리 찾고 덜 헤맵니다.
Why:    '또한'과 '이를 통해'가 실제 관계를 설명하지 않는다. 결과만 말하면 된다.

Before: 단순한 도구가 아니라 새로운 작업 방식입니다.
After:  작업 방식 자체가 바뀝니다.
Why:    It's not X, it's Y를 옮긴 것. 긍정으로 바로 말하면 된다.

Before: 따라서 다양한 사용자의 니즈를 효과적으로 충족할 수 있다고 할 수 있습니다.
After:  그래서 사용자가 원하는 걸 대부분 처리합니다.
Why:    채움말 둘에 회피형 서술. 남는 내용이 한 줄이다.

Before: 핵심 인사이트와 니즈를 기반으로 어프로치를 설계합니다.
After:  확인한 내용과 사용자에게 필요한 걸 놓고 접근 방식을 정합니다.
Why:    영어 단어가 문제가 아니라 영어식 문장 구조가 문제다.
